## The rules that would have saved wasted runs
1. **Name the Python you mean** (`py -3.14` or a venv), never a bare `python` that may lack ezdxf. Raw strings or forward slashes for every Windows path in Python (`\U` in `C:\Users` is a SyntaxError).
2. **Write patch scripts, skill files and .scr generators with a file-write tool or Python**, not shell heredocs holding nested quotes (they fail with "unexpected EOF while looking for matching"). Patch with an exact-count guard: `assert s.count(a) == n` before `replace`. Make multi-step patches idempotent. Some agent shells hand a doubled backslash to the shell as ONE, so Python inside a heredoc sees `\v`, `\b`, `\3`, `\f` and writes control characters into Windows paths. Any text holding a Windows path goes through a file-write tool or uses `chr(92)`; scan written text for `ord(c) < 32`.
3. **Never chain build steps with `;`**. `py -3.14 emit.py; if ($LASTEXITCODE -ne 0) { exit 1 }` before the build, or a crashed generator lets AutoCAD build the OLD script.
4. **Delete old outputs first** (DWG, sheet PDFs, log) so a failed run cannot pass on stale files.
5. **accoreconsole only through PowerShell** `Start-Process ... -ArgumentList "/i",<dxf|dwg>,"/s",<scr>,"/l","en-US" -NoNewWindow -PassThru -RedirectStandardOutput log` with `WaitForExit(ms)` and `Kill()`. Always `/i`. Launch from a scratch folder (it drops `ErrorReports\`). Probes 60 to 120 s, full build 420 s. Under Git Bash `timeout` it sat at `Command:` and did nothing. Python also works: `subprocess.Popen([exe,"/i",dwg,"/s",scr,"/l","en-US"], stdout=logfile, stderr=subprocess.STDOUT, cwd=scratch)`, then `wait(timeout)` and `kill()` on TimeoutExpired ([core_tests.py](../../../autocad-kb/_verified/scripts/core_tests.py)).
6. **Logs are UTF-16-LE**: `open(p,"rb").read().decode("utf-16-le","ignore")`. Emit your own markers `(princ "SHEET X DONE")`; each shows twice.
7. **A blank line at `Command:` repeats the last command** and hangs. One blank only to end a selection or a `-LAYER` loop. One wrong answer desyncs every later line: read the log at the first `; error` or prompt mismatch.
8. **`"_non"` before every point** in LISP (running osnaps give "Value must be nonzero").
9. **No `.lsp` loading** while SECURELOAD blocks it ("File load canceled"). Inline LISP, one form per line. Do not change SECURELOAD. With SECURELOAD 1 and an empty TRUSTEDPATHS (check yours), any .lsp, .dll (NETLOAD: "Unable to load ... assembly") or .arx outside the AutoCAD install folders is refused. Two documented ways to load your own code, both the user's decision and the user's to do: add a trusted folder (TRUSTEDPATHS), or install the code as a bundle under `%PROGRAMFILES%\Autodesk\ApplicationPlugins`, where Autodesk treats plug-ins as trusted without a signature check ([Autodesk help](https://help.autodesk.com/view/OARX/2027/ENU/?guid=GUID-5E50A846-C80B-4FFD-8DD3-C20B22098008); needs admin; loads at every start).
10. **Paths at AutoCAD prompts:** forward slashes, no spaces, Windows form (`cygpath -m`). An MSYS `/tmp/...` path shifts every prompt after it. Layout names: no spaces.
11. **-PLOT tails differ by sheet:** a shaded-viewport sheet ends `_Q _C 250 _N _Y`; a 2D-only sheet ends `_N _Y`. The shaded tail on a 2D sheet loops "Yes or No, please" forever. Save the DWG BEFORE plotting so a plot hang can be replotted alone from the DWG.
12. **Status checks from artifacts, not memory:** PDF and DWG mtimes, `Get-Process accoreconsole` CPU delta over 3 s (about 3 s CPU per 3 s = spin loop, hung), log tail. About 5 s per shaded sheet is normal; over 30 s is hung. A full model build took 100 to 140 s alone, up to 195 s with MEP open.
13. **Verify every sheet visually:** render to PNG (PyMuPDF `get_pixmap(dpi=110)`) and look. Shaded viewports are raster images: `page.get_images()` sizes prove each viewport rendered (a 2899x4 image is a sliver). Overflow test: text blocks past x = 1190 pt.
14. **One source of truth:** the same op list drives solids, takeoff counts (`counts3d.json`), calcs and the Excel bridge. Re-run counts, calc book and calculator after any model change; calcs that read geometry run after it is built.
15. **Label anchors are keyed to model part names.** Change both in the same patch and run the emitter at once (`KeyError` on a part name otherwise).
16. **Inch marks inside LISP strings** must be `\"`, which is `\\"` in Python source.
17. **Excel:** cell notes over COM: `Range.AddComment(text)` IGNORED the text on the Excel build tested (the note read only the author name). Use `rng.AddComment()` then `rng.Comment.Shape.TextFrame.Characters().Text = text[:250]` and `.Characters(n+1).Insert(chunk)` for the rest; read back with `Comment.Text()` (`Comment.Text(Text=...)` and `TextFrame2` both raise). The xlsx skill's `recalc.py` failed on Windows (AF_UNIX). Use Excel COM (`scripts/xl_recalc.py`, retries a rejected Close). Edit the user's workbooks through Excel COM on a copy, diff against the original, then replace. Only `#...` values are errors; `""` formulas read as None. Zero errors is not correct: eyeball the Summary numbers.
18. **COM on AutoCAD MEP:** pywin32 name lookup fails (`AttributeError <unknown>.Name`). Use raw IDispatch (`scripts/mepcom.py`). Keep all COM on the main thread ("CoInitialize has not been called" in threads).
19. **Never leave an MEP prompt open.** Every later COM call is then rejected ("Call was rejected by callee"). Send the WHOLE command in ONE SendCommand string, ending on a prompt that exits. Nothing cancels a command stuck inside SendCommand (tested): `\x1b`, `\x03` cannot even be sent, and Escape posted to the command-line window (`RICHEDIT50W` child of `AfxMDIFrame140u`) did nothing. Only killing acad.exe recovers; the next launch then stops on a "Drawing Recovery" dialog that blocks COM until closed with WM_CLOSE (`win32gui.PostMessage(h, WM_CLOSE, 0, 0)`).
20. **Do not take over the user's mouse or keyboard.** Drive apps by COM and scripts, keep MEP minimized, close dialogs by window message (`DialogGuard` in mepcom.py). Screenshots for checking are fine; clicks and typing are not, unless the user asks.
21. **Look it up before you try it.** The knowledge base sections answer most "what is the prompt / which variable / why does it do that" questions from Autodesk's own pages. Cite the help page when you tell the user something. Then still test live: docs describe dialogs, not your script.
22. **Validate every value before it reaches an MEP prompt.** A space ends the answer (most routing preference names have spaces: answer by index number, or pick a space-free name), a misspelled name re-prompts forever, and a bad token can spin MEP at the prompt (60% CPU, all COM rejected, kill needed). Read names from the drawing first (dictionaries via LISP, systems via COM).
23. **MEP COM writes need typed values:** points as `mepcom.pt(x,y,z)` (VT_ARRAY|VT_R8; a tuple fails E_INVALIDARG), `SystemName` as `"CHWS (CHWS)"` (name plus abbreviation; plain `"CHWS"` fails E_FAIL).
24. **Scripts cannot run dialog commands:** use hyphen forms (-PLOT, -PUBLISH, -EXPORT, -PDFIMPORT, -INSERT, -LAYER), full command names (aliases are not allowed in script files, [Autodesk help](https://help.autodesk.com/view/OARX/2027/ENU/?guid=GUID-FE9AE544-F537-4D3B-8F75-B76484513787)), names with spaces in double quotes, last line blank. **Leave FILEDIA alone in scripts:** at its default 1, AutoCAD shows ordinary prompts instead of file dialogs while a script or AutoLISP is active ([Autodesk help](https://help.autodesk.com/view/ACD/2027/ENU/?guid=GUID-99736BD7-E60E-4F4A-83F7-436B6F9C67A1); tested: `-PDFIMPORT` in the console took the file name at the prompt with FILEDIA 1). Set FILEDIA 0 only for commands typed into the GUI through SendCommand, and then save and restore it with `scripts/uservars.py` (`save()` first, `restore()` at the end; it also restores at exit). It is saved per user: scripts that set it and never restore it leave the user's own file dialogs off. Same rule for CMDDIA (in-place editor for DIMEDIT and QLEADER, some dialogs), LOGFILEMODE and BACKGROUNDPLOT. -PLOT/-PUBLISH in a script run in the foreground whatever BACKGROUNDPLOT says ([Autodesk help](https://help.autodesk.com/view/ACD/2027/ENU/?guid=GUID-713029B7-B5AC-4860-BE2E-74878D418EA4)). Run `_IMAGEASYNCWAIT` after opening any drawing with raster images, before PLOT, SAVE or EXPORT (2026+ loads images in the background).

## Tested setup
- AutoCAD 2027, `C:\Program Files\Autodesk\AutoCAD 2027\` with `accoreconsole.exe`. COM `AutoCAD.Application.26`.
- AutoCAD MEP 2027 (same acad.exe, MEP profile).
- draw.io desktop for diagrams to PDF: `%LOCALAPPDATA%\Programs\draw.io\draw.io.exe -x -f pdf -o out.pdf in.drawio`.
- Python 3.14: ezdxf, PyMuPDF, openpyxl, pywin32, cadquery, build123d, shapely, matplotlib, reportlab. comtypes is not needed.
- .NET: PowerShell 7.6 runs on .NET 10 and carries the C# compiler, which builds AutoCAD 2027 (.NET 10) plug-ins without the SDK ([dotnet plug-in build](../../../autocad-kb/_verified/2026-10-17-dotnet-plugin-build.md)). Loading them is blocked until a folder is trusted (rule 9).
- Local API help: `C:\Program Files\Autodesk\AutoCAD 2027\Help\*.chm` (MEP COM: buildingauto-reference, plumbingauto-reference, scheduleauto-reference; MEP .NET: Aecb*Mgd.chm).
- **Registry-saved settings to know about:**
  - The Core Console reads profile `<<Unnamed Profile>>` under `HKCU\Software\Autodesk\AutoCAD\R26.0\ACAD-A101:409`. A profile can hold non-default PDF import settings (for example PDFIMPORTFILTER 1 = no geometry, PDFIMPORTMODE 3 = one block, PDFIMPORTLAYERS 1). Read them, set what you need inside any import script, and restore them after. The MEP key (`ACAD-A106:409`) may store none and use the defaults 8, 6 and 0.
  - FILEDIA is stored as `FixedProfile\General Configuration\FileDialog` under each key (A101 = plain AutoCAD, A106 = every MEP shortcut). Keep it at 1 (rule 24).
  - A GUI window writes FILEDIA to the registry the moment it is set (not at close). The Core Console always starts with FILEDIA 0 and never saves it, whatever the registry holds, so a console reading says nothing about the user's windows. The console does save CMDDIA.
  - Shortcuts: "AutoCAD 2027 - English" = `/product ACAD`; "AutoCAD MEP 2027 - English" = profile "AutoCAD MEP (Global)"; "(US Imperial)" = profile "AutoCAD MEP (US Imperial)".

## Recipes

### DXF to DWG
`/i x.dxf`, script `_.SAVEAS` / `2018` / `C:/scratch/x.dwg` / `_.QUIT` / `_Y`. ezdxf base: `ezdxf.new("R2018", setup=True)`, `doc.header["$INSUNITS"] = 1`, model in inches, `layer.rgb` per layer (drives shaded colors). `$MSLTSCALE` is not a valid header key. Cast numpy floats with `float()` before writing LISP. `doc.audit()` should report 0 errors.

### PDF floor plan in
- **Default: native `-PDFIMPORT`, headless.** Verified on a test page and on a full owner floor plan: about 110,000 paths imported in 10 to 19 s (16 to 25 s per run). The dialog PDFIMPORT is missing from accoreconsole, but the command-line form works.
  - Save, then set `PDFIMPORTFILTER 8` (1 = no geometry) and `PDFIMPORTMODE 6` (3 = one block).
  - To get the source PDF's layers as `PDF_<name>`, also set `PDFIMPORTLAYERS 0` (1 = only PDF_Geometry, PDF_Solid Fills and PDF_Text).
  - Then `_-PDFIMPORT`, `_F`, `<pdf>`, `<page>`, `_non`, `<insert pt>`, `<scale>`, `0`, and restore every variable you changed. Do not touch FILEDIA: a script gets the file name prompt anyway (rule 24).
  - Result: LWPOLYLINE, ARC and CIRCLE (Beziers fitted); fills as 2D SOLID at 50% transparency; TrueType text as MTEXT (style "PDF ArialMT"); SHX text as polylines. Lineweights and true colors are kept. The page's lower-left corner lands on the insertion point.
- **Scale: read the PDF's /VP first** (PyMuPDF `doc.xref_get_key(page.xref, "VP")`).
  - If it holds `/Measure ... /X [<< /C n >>]`, AutoCAD uses it: scale 1 gives the source drawing's units (for example inches; then scale 1/12 gives feet).
  - Without /VP: 1 PDF inch = 1 unit (scale 192 for a 1/16" plot, 96 for 1/8").
  - Either way, confirm with known dimensions (column bays, door widths, printed room areas).
  - Native coordinates matched raw x C within 40 ppm. A PDF itself is quantized to about 0.12 pt.
- **/Rotate pages import as displayed** (270 tested; the same page with /Rotate removed came in turned 90 degrees). Answer 0 at the rotation prompt.
- Bit tables: [core console tests](../../../autocad-kb/_verified/2026-10-17-core-console-tests.md).
- **PyMuPDF route:** `page.get_drawings()` > LWPOLYLINE (flatten Beziers), black fills > solid HATCH, `get_text("dict")` > TEXT. Multiply by `page.rotation_matrix` (drawings come unrotated).
  - Take the scale from the PDF's /VP measure, not from a fit (see Underlay fit).
  - On the same plan: about 65 s, a similar entity count.
  - By design it is a thin gray underlay: it drops gray and white fills, flattens weights and curves, and uses one layer.
  - Use it for a styled underlay inside an ezdxf build, or for feature extraction in Python (equipment outlines by color, columns by stroke width). Each path's PDF layer is in `d["layer"]`. Native with PDFIMPORTLAYERS 0, then DXFOUT and ezdxf, also gives features per source layer.
- Not tested yet: scanned (raster-only) PDFs, multi-page sets (one `-PDFIMPORT` per page), PDFs from Revit or Bluebeam.
- `-PDFATTACH` crashes accoreconsole (0xC0000005).

### Layout plot
ezdxf `lay.page_setup(size=(17,11), margins=(0,0,0,0), units="inch", scale=16, name="ANSI full bleed B (17.00 x 11.00 Inches)", device="DWG To PDF.pc3")`, delete "Layout1". `Viewport.frozen_layers` freezes per viewport.
- 2D: `_.-PLOT _Y <layout> "DWG To PDF.pc3" "ANSI full bleed B (17.00 x 11.00 Inches)" _I _L _N _L 1:1 0,0 _Y monochrome.ctb _Y _N _N _N <pdf> _N _Y`
- Shaded: `... _I _L _N _W 0,0 17,11 _F 0,0 _Y acad.ctb _Y _N _N _N <pdf> _Q _C 250 _N _Y` (Window 0,0 17,11 because MVIEW-made viewports plot tiny with area Layout).
- Model space: `_.-PLOT _Y Model <pc3> <paper> _I _L _N _E _F _C _Y monochrome.ctb _Y _A <pdf> _N _Y`.
- Model space, fixed window without typing points: `(setvar "LIMMIN" (list x0 y0))`, `(setvar "LIMMAX" (list x1 y1))`, then plot area `_L` (Limits) in place of `_E`. Two different drawings came out with identical framing.
- `monochrome.ctb` prints all black: split supply and return by linetype and weight. `acad.ctb` for shaded sheets.
- Color in a plotted set: give entities `.rgb` (true color) and plot with acad.ctb. ACI 7 still plots black; true color 255,255,255 plots white (use it for symbol masks).
- Harmless: "Cannot append to plot stamp log file". Trust the file and a render.

### 3D solids (inline LISP)
- Helpers: `(defun cyl (p0 p1 r) (command "_.CYLINDER" "_non" p0 r "_A" "_non" p1))`; CONE `_T` for reducers; SPHERE, BOX, TORUS, SUBTRACT; elbows: `UCS _ZA`, CIRCLE, `UCS _W`, REVOLVE 90 about a 2-point axis. `(setvar "CMDECHO" 0)`, set `CLAYER` per batch.
- About 100 solids/s (5,720 solids in 75 s). Check `(sslength (ssget "X" '((0 . "3DSOLID"))))` equals the op count.
- Viewports from LISP: `LAYOUT _S <name>`, `PSPACE`, `MVIEW` corners; id = group 69 of `(entlast)`; skip id 1 (the layout itself) or CVPORT rejects it. `MSPACE`, `(setvar "CVPORT" id)`, `-VIEW _SWISO` (VPOINT does NOT work in viewports from LISP; check `(getvar "VIEWDIR")`), `UCS _W`, `VSCURRENT _R`, `VSOBSCUREDEDGES 0` and edges off (else hidden pipes show through), `ZOOM _C pt h`, `VPLAYER _F <layers> _C ""`, then `PSPACE`, `MVIEW _S _A`, `MVIEW _L _ON`. Rendered shade mode hangs: use As displayed + Realistic.
- Model-space iso plot on an ezdxf drawing: `-VPORTS _SI` first, then `VPOINT _R 315 35`.
- Hide clutter, keep counts: hangers on their own layers, `-LAYER _OFF M-HGR-STRUT,M-HGR-ROD,M-HGR-CLEVIS,M-INSUL ""` before SAVEAS (piping detail matters most). Freeze equipment per viewport to show what is behind it.
- Labels: paper-space leaders projected from model points (view dir N, X = unit(Z x N), Y = N x X). Width estimate `0.085*0.76*len+0.14` in; clamp inside the viewport; an automatic placer (16 directions, scores overlaps, leader crossings, covered dots) must print `labels still overlapping: []`. MTEXT mask `set_bg_color("canvas")`.

### STEP
CadQuery/build123d write mm STEP whatever unit you ask for. Model in inches, scale x25.4 before export, `$INSUNITS=1` in the base drawing; AutoCAD lands it 1:1. Import: `_.IMPORT <step>` (in a script FILEDIA can stay 1, rule 24), `_.DELAY 15000`, then EXPLODE the "Open CASCADE STEP translator" block (two levels). build123d pipe: `FilletPolyline(..., radius=1.5*NPS)` + `sweep(transition=Transition.RIGHT)`. `scripts/fusion_step.py` writes a colored STEP assembly (one part per layer) from an op list.

### Reading a DWG back headless
`_.-LAYER _? *` (one blank), `_.-LAYOUT _?`, `_.SELECT _ALL` (one blank) prints `N found` (it skips objects on frozen layers; `(sslength (ssget "X"))` counts everything); `_.DXFOUT <path> 16` then ezdxf `Counter(e.dxftype() for e in msp)`.

### Raster logo to vector in a title block
No tracing tools needed: weight each pixel between the logo's two colors (0 to 1), run contourpy's filled marching squares at 0.5 (FillType.OuterOffset gives outer rings with their holes), simplify 0.35 px, and draw each polygon as one hatch (first path external, the rest holes). AutoCAD's DWG To PDF then splits each holed hatch into thin strips that show as hairlines in viewers: redraw the same polygons on the PDF with PyMuPDF (`shape.draw_polyline` per ring, `finish(even_odd=True)`). Keep the DWG hatch so AutoCAD still shows the logo.

## 3D build architecture (a proven layout)
`geom.py` (primitives > OPS `(layer, kind, args)`, tallies `TK[name] += 1`, `TKL[name] += ft`, `side_layer(system,size)`) > `model.py` (Run class: points in ft, per-segment sizes, start/end `open|cap|on:<run>`, vents, keep-outs; inline parts `inl(run, pt, kind)`; hangers slide BACK from keep-outs, never forward; supports; equipment; `RUNS`, `build_all()`) > `details.py` (typical details and parts gallery far off the building, tallies snapshotted and restored) > `emit.py` (base DXF + .scr + sheet layouts + labels + `counts3d.json`) > `run_build.ps1` > `post.py` (log scan, merge with `insert_pdf`, `save(garbage=3, deflate=True)`, PNG previews) > `update_calculator.py` (Excel COM bridge). Calcs: `hyd.py` + `calcs.py` > `calc_book.py` (live formulas) > `xl_recalc.py`. The MEP and STEP scripts here (`mep_build.py`, `mep_restore.py`, `fusion_step.py`) import `geom` and `model` from the folder you pass with `--src`.

## AutoCAD MEP
- **Launch:** `acad.exe /ld "C:\Program Files\Autodesk\AutoCAD 2027\AecBase.dbx" /p "AutoCAD MEP (US Imperial)" /product "MEP" /language "en-US" /nologo`. Without `/p` it can come up as Architecture with no pipe parts ("No Part Found" / "Choose a Part" dialogs). Live profile switching does not reload catalogs. Profiles: `HKCU\Software\Autodesk\AutoCAD\R26.0\ACAD-A106:409\Profiles`. Record the default before changing it and restore it after: a launch with `/p` makes that profile the default. COM answered from 45 s to about 3.5 min after a minimized launch: poll `Documents.Count` for up to 6 min. `PRODUCT` reads "AutoCAD" even in MEP; check `CPROFILE`.
- **MEP pipe commands exist only in the GUI**, not accoreconsole.
- **But MEP drawings can be READ headless (verified):** a plain accoreconsole run auto-loads the MEP object enablers when it opens an MEP DWG (objects are real `AECB_PIPE` / `AECB_PIPEFITTING`, not proxies). `entget` gives only type/handle/layer and the Core Console has NO ActiveX (vla-/vlax- do nothing, per its help page), but `_.LIST` on a selection (use an `(ssget "X")` set as in the takeoff tool below; `_ALL` skips frozen layers) prints per object: Length, Cut Length, Start/End Point, Slope, Routing Preference, System Reference, Style Reference (size and part name), Insulation Thickness, fitting Connection Points. Parse the UTF-16 log for takeoffs from MEP drawings with no MEP window open. Core Console switches are `/i /s /product /l /isolate /readonly /p /loadmodule` (no `/ld`). Detail: [core console tests](../../../autocad-kb/_verified/2026-10-17-core-console-tests.md).
- **Takeoff tool (verified):** `py -3.14 scripts/mep_takeoff.py <a.dwg> [b.dwg ...] --out <folder>` copies each DWG, runs the Core Console with `_.LIST` on an `(ssget "X")` set in decimal units (`_ALL` skips frozen layers; architectural text rounds to LUPREC), and writes `<name>_objects.csv` (one row per pipe and fitting) plus `<name>_summary.csv` and `.txt` (pipe ft by system and size, fittings by type and size); it checks counts against the database and names any xrefs it cannot see. Set `ACCORECONSOLE` if AutoCAD is not in the default folder. LIST honors LUNITS and LUPREC; no paging at 700 objects; the LIST Slope field is an angle in degrees and reads 0 on risers; MEP puts a main-size pipe stub between a tee and a branch reducer. Proven against COM and the drawn lengths: [takeoff test](../../../autocad-kb/_verified/2026-10-18-mep-takeoff-test.md).
- **COM:** `scripts/mepcom.py`: `app() get() call() var() send() wait_idle()` over raw IDispatch; `DialogGuard` logs and cancels dialogs by message. New drawing: `call(get(app(),"Documents"),"Add",<dwt>)`; open: `call(docs,"Open",<dwg>)`. Minimize: WindowState 2. Also `put(o,name,val)`, `pt(x,y,z)`, `aec(progid)` (GetInterfaceObject + Init on the active drawing), `names(coll)`, `connected(ent)`. `scripts/uservars.py` puts back FILEDIA, CMDDIA, LOGFILEMODE and BACKGROUNDPLOT after a GUI run; `mep_build.py` uses it.
- **Two acad.exe at once (verified):** both register the same `!{CLSID}` name in the Running Object Table, and every entry, like GetActiveObject, gives the FIRST one registered ([Autodesk help](https://help.autodesk.com/view/OARX/2027/ENU/?guid=GUID-0225808C-8C91-407B-990C-15AB966FFFA8)). A second MEP started by Popen cannot be driven by COM while the first runs; use `launch()` (next bullet) for a second one. `mepcom.bind(proc.pid)` ties every helper (app, doc, var, send, aec, wait_idle, dialogs, DialogGuard) to one acad.exe and fails closed (com_error MK_E_UNAVAILABLE) instead of reaching the other; `app(pid)`, `dialogs(pids)` and `DialogGuard(pid=)` do it per call; unbound calls work as before. `py -3.14 scripts/mepcom.py` prints the PID map. ### Whole model as native MEP pipe (verified)
Proven on a whole-building chilled water model: over 100 runs and about 550 MEP objects (pipes, elbows, reducers, tees) plus several thousand part solids in about 8 min, 0 dialogs, every object checked against the plan. Scripts: `scripts/mep_build.py` (stages all, pipes, plot) and `scripts/mep_restore.py` (puts the solid pipe back for any run MEP could not draw).
- **Pipeline:** tag the op list (pipe and the fittings MEP can make vs solids) > accoreconsole base DWG of the solids > plan the runs > in MEP: copy of the Routing Preferences drawing, `-INSERT *base.dwg`, systems by COM, one `-AECBPIPEADD` per run > verify by COM > final layers > named views > plot views headless from a copy.
- **MEP picks connections by SCREEN PROJECTION.** A typed 3D point that lands, in the current view, on any visible pipe connects to it (even 200 in. away in depth) and the run continues at that pipe's elevation. Fix: give each run its own temporary layer (`R-<run>`), and before each run freeze every layer except 0, M-Pipe-Std and the intended parent's layer; draw in an iso view (SEISO); move new objects off M-Pipe-Std right after each run. Check each run's points in Python against the visible parents in projection and pick another iso view if one lands on a pipe.
- **Plan view breaks risers:** a branch typed onto a vertical pipe in plan view grabs the pipe's END (elbow). Iso view only.
- **A branch point on a straight-through vertex** (pipe joint) connects to the pipe end: merge collinear same-size vertices before drawing.
- **Glued (Sch 40 PVC) makes:** pipe, 90 elbows, equal tees, concentric reducers (catalog pairs 4x3, 4x2, 3x2, 2x1-1/2, 2x1, 1-1/2x1, ...). A smaller branch gets a main-size stub plus reducer automatically (about 5 to 10 in. long) when a reducer pair exists, otherwise "Choose a Part". No reducing tee is in the routing preference, and the catalog has no 4x4x1, 4x4x1-1/2, 3x3x1, 3x3x1-1/2 reducing tee or 4x1-1/2 reducer. Routing preferences can only be edited in Style Manager (GUI). So: equal tees native; at reducing tees keep the model's tee solid and start the branch at the tee outlet (unconnected run); split runs at missing reducers.
- **Run ending on a pipe:** MEP asks `Connect or preview Next solution 1(n)`, Enter accepts, then it restarts at `Start point` (Enter exits): two blanks after the last point. A run tied natively at BOTH ends can come out with the far tee turned sideways and a jog (solution 1). Fix: split off the last leg, start it on the far main and stop at the last corner; end the rest on that leg's open end, where MEP adds the elbow.
- **Layer descriptions: use COM `Layer.Description`, not `-LAYER _D`.** When a layer already has a description, `-LAYER _D` asks an extra replace question; the unanswered question desynced the answers and pinned MEP at a full core (Escape posted to MDIClient did nothing; killed by PID). `-LAYER _TR <0-90> <layers>` asks no extra question.

- **Prompt watchdog (no COM):** a SendCommand that leaves a prompt open blocks or leaves MEP waiting. A thread that reads the drawing's command log (LOGFILEMODE 1) and, after 2.5 s quiet at a `Next point` / `Start point` / `Connect` prompt, posts `WM_CHAR 13` to the MDIClient child of the AfxMDIFrame140u window answers it (verified). - **Verify by COM:** filtered selection set (`SelectionSets.Add`, `Select 5` with VT_I2/VT_VARIANT filter arrays) over AECB_PIPE,AECB_PIPEFITTING; read Layer, SizeName, SystemName, Connectors; check pipe ends on the planned centerline, elbows at corners, reducers at size changes, tees at native branches, length closure. ## 2D construction sets ("official blueprints") from the model
A model-driven set of about 9 ANSI D sheets builds in about 50 s.
- **Hidden lines without AutoCAD:** project each op (cyl, cone, sph, box, torus, elb, strut, cstrap, wall) to a 2D convex hull (elbows: union of hulls of 6 sub-segments), sort by nearest depth, draw each outline minus the union of the ones already drawn (`shapely`; grid buckets keep it fast). A 5,000-op model gives a plan, 3 elevations and 6 details in about 3 s. Clip cylinders to the view box (Liang-Barsky) so pipes running out of a section show as cut circles. Each view goes in model space at its own offset; layouts get viewports at real scales.
- **Oblique plan views:** a projector that takes any linear basis (R = (s, 0, k s), U = (0, s, k s), N along (-k, -k, 1)) draws equipment hidden-line straight into paper space. Scale sphere radii too (unscaled gives giant circles in paper inches), and draw big flat pads as plain outlines (a painter sort by nearest corner puts a pad in front of the equipment standing on it).
- **Sheet size:** for a set meant to print like a standard set, use ARCH D, 24 x 36. `ARCH full bleed D (36.00 x 24.00 Inches)` works in DWG To PDF.pc3 (a probe gave page 36.00 x 24.00 and a 10 in. paper line plotted at 10.000 in.). Put a PRINT box in the title block: full size 24 x 36, 12 x 18 is half scale, and a 1 in. check bar.
- **Re-size a finished set without re-laying it out:** record the layout's entity count after the title block, build the sheet as before, then move everything after that index by a fixed offset: `e.transform(Matrix44.translate(dx, dy, 0))` for each entity, and for VIEWPORTs (skip id 1) add the offset to `dxf.center` only, so the model view and the scale stay put. ezdxf `Dimension.transform` also moves the dimension's geometry block (checked in AutoCAD's plot). Check afterward: each paper DIMENSION's measured length times its viewport's view_height/height equals its text.
- **Plot:** `ANSI full bleed D (34.00 x 22.00 Inches)` works in DWG To PDF.pc3. Use `acad.ctb` with every layer ACI 7 and the floor plan underlay on ACI 253 (lines) and 252 (text): prints black with a light gray background. Return line DASHED with `$PSLTSCALE 1`, `$LTSCALE 0.5`.
- **Text width:** AutoCAD plots Arial caps at about **0.86 x height per character** (measured from the PDF). 0.70 overflowed the notes into the title block. Bold about 0.91.
- **Labels:** paper-space placer that rejects overlaps and scores coverage of the view's own polygons (paper coords via an affine transform of the view items). **Masks: ezdxf `add_wipeout` does NOTHING in an AutoCAD 2027 plot (tested: neither paper lines nor viewport content hidden). Use a solid HATCH with `true_color` white (255,255,255) in paper space behind each label or valve symbol: it hides both.** Never let one view's placer see another view's viewport box as free space (and do not add a viewport's own box to its own obstacle list).
- **Underlay fit:** fit the floor plan PDF to model coordinates by least squares on matched features (equipment outlines), not on one assumed dimension; report the max residual. Then check the fit's scale against the PDF's own /VP scale: in one test the fit came out 3.6% under it, while printed room areas and column bays agreed with the PDF's scale, not the fit.
- **Fusion drawing API (see the fusion skill):** automatic drawings from a saved design work (`createDrawing`, isometric with parts list, orthographic sheet, one dimensioned sheet per part, PDF and DWG export). The build tested could not place views, add text or fill table cells by API, so construction sets stay on this 2D pipeline.
- **Raster images do not plot in accoreconsole** (no error, the IMAGE entities are just skipped). Keep the IMAGE links in the DWG for full AutoCAD, and stamp the PNGs into the plotted PDF with PyMuPDF `page.insert_image` at the same rectangles.
- **Keep the construction set to line drawings** (plans, sections, isometrics, details, schedules). Shaded 3D shots go on their own PDF, as few as possible: one page, 4 views, same title block, status FOR REFERENCE.
- **Mark every fitting:** wrap the model's fitting builders before `build_all()` and record the outermost call; filter detail samples by location, and restore the tallies afterward so the takeoff never shows them.
- **Check what a valve move hits:** after moving any inline part, check it against supports and clamps too, not just pipe segments.
- **One model, more than one editor:** before building sheets, prove the build source matches what Fusion shows (for example the bounding box of a part that moved). Give each process or person one folder to own, and build from the owner's final copy only.
- **Dimension chains:** `add_linear_dim(...)` then `DimStyleOverride.set_location(pt, leader=False, relative=False)` BEFORE `render()` moves a short segment's text below the line; writing `dxf.text_midpoint` after `render()` does nothing. Alternate odd short segments below. Captions for a chain go at the right end on the baseline: below collides with the view title, left can run off the sheet. A scale label table needs an entry for every detail scale used (8 = 1-1/2").
- **Detail sheets from the model:** one `detail()` call per cell: region (ft), basis, den, cell frame; elevation tags and dimension boxes registered as placer obstacles BEFORE labels; notes placed just above the view and also registered. The view's own viewport box must NOT be an obstacle (29 of 60 labels failed when it was).
- **Work in a private copy:** have the sheet build read its model and job paths from environment variables, so a scratch copy builds against the job folder's model without touching it.
- **After adding building context** (walls, columns, outlines from the floor plan), put it on A-BLDG-* layers, keep it out of hidden-line plant views, and always run a pipe-vs-building clash check.

## Layout changes: check clashes before building
After moving any run, screen the area in Python before the 2 to 3 minute build: sample every pair of unconnected segments, flag centerline distance under the two ODs plus 1 in. Moving one penetration can ripple into riser heights, headers, tie-ins, stand heights, equipment nozzle sides and calc code that names runs: grep every use of the run names and constants first.
- Whole model: keep a clash script that checks every pipe segment against walls, columns and equipment boxes and against every other pipe (drop ends at equipment nozzles excluded). Run it after any layout change.
